# Права, история правок и API

## Роли

| Роль | Что может |
|---|---|
| Читатель (без входа) | Читать, искать, смотреть историю и старые ревизии |
| Предложивший (вошёл через GitHub, роль `reader`) | То же и отправлять предложения правок |
| Админ | Правит напрямую, решает по предложениям, ведёт ключи и пользователей |
| API-ключ | Только то, что разрешено его набором прав |

Все проверки прав находятся в одном месте, `auth/policy.rs`. Маршруты спрашивают
`policy.can(actor, action)` и не содержат своих `if role == ...`.

## Ревизии и история

- Каждая запись страницы создаёт ревизию с полным текстом, автором, временем и комментарием.
- **Просмотр старой версии.** `/{lang}/{slug}?rev=12` показывает страницу так же, как обычную,
  но с плашкой: «Старая версия от даты, автор. Перейти к актуальной».
  Открыть можно любую ревизию, вплоть до первой.
- **История.** `/{lang}/{slug}?history`: дата, автор, комментарий, размер правки (+/− символов).
- **Сравнение.** Любые две ревизии, построчный diff, как в git.
- **Откат.** Админ выбирает старую ревизию, её текст записывается как новая ревизия
  с комментарием «Откат к №12». Откат тоже можно откатить.
- **Удаление страницы** скрывает её от читателей. Админ видит её и может восстановить.

## Предложения правок

1. Читатель входит через GitHub и жмёт «Предложить правку» на странице.
2. Открывается редактор с текущим текстом. Предложение запоминает `base_rev_id`.
3. Предложение попадает в очередь со статусом `open`.
4. Админ видит diff предложенного текста против `base_rev_id` и против текущей ревизии.
5. **Принять:** создаётся ревизия, автор которой предложивший, а в комментарии указан принявший.
   Если текущая ревизия новее `base_rev_id`, админу показывается трёхстороннее сравнение
   (база, текущая, предложенная) и он правит итог сам. Автослияния нет.
6. **Отклонить:** статус `rejected` и причина. Автору видно решение на его странице «Мои предложения».

Защита от спама: вход только через GitHub, не больше N открытых предложений на человека,
не больше M отправок в сутки, админ может заблокировать пользователя (`blocked_at`).

## Админка

Адрес `/admin`, доступ только у админов. Разделы:
- **Страницы:** дерево разделов, создание, правка, удаление, восстановление.
- **Редактор:** Markdown, живое превью через тот же `render`, кнопки вставки крафт-сетки,
  плашек подсказок и плашки версии.
- **Предложения:** очередь, diff, принять или отклонить.
- **История и откат** для любой страницы.
- **Ключи API:** создать (ключ показывается один раз), посмотреть последнее использование, отозвать.
- **Пользователи:** список, блокировка, назначение админа.
- **Картинки:** загрузка и список (`media`).

## API

Заголовок `Authorization: Bearer <ключ>`. Ответы в JSON, ошибки в формате
`{"error": "код", "message": "текст"}`.

| Метод и путь | Права | Назначение |
|---|---|---|
| `GET /api/pages` | read | Список страниц с актуальной ревизией |
| `GET /api/pages/{slug}?lang=ru` | read | Страница и метаданные |
| `PUT /api/pages/{slug}?lang=ru&summary=...` | write | Создать или обновить, тело запроса — Markdown |
| `GET /api/pages/{slug}/revisions?lang=ru` | read | История |
| `GET /api/export` | export | Все страницы архивом Markdown |

Запись через ключ создаёт обычную ревизию с автором «ключ: название». Если тело совпадает
с текущей ревизией, новая ревизия не создаётся (повторная заливка из CI безвредна).

Коды ошибок: 401 нет или неверный ключ, 403 не хватает прав, 404 нет страницы,
422 неверный slug или язык, 429 лимит запросов (с заголовком `Retry-After`).
