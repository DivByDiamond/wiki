# Права, история правок и API

## Роли

| Роль | Что может |
|---|---|
| Читатель (без входа) | Читать, искать, смотреть историю и старые ревизии |
| Предложивший (вошёл через GitHub, роль `reader`) | То же и отправлять предложения правок |
| Админ | Правит напрямую, решает по предложениям, ведёт ключи и пользователей |
| API-ключ | Только то, что разрешено его набором прав |

Все проверки прав находятся в одном месте, `auth/policy.rs`. Маршруты спрашивают
`policy.can(actor, action)` и не содержат своих `if role == ...`.

## Ревизии и история

- Каждая запись страницы создаёт ревизию с полным текстом, автором, временем и комментарием.
- **Просмотр старой версии.** `/{lang}/{slug}?rev=12` показывает страницу так же, как обычную,
  но с плашкой: «Старая версия от даты, автор. Перейти к актуальной».
  Открыть можно любую ревизию, вплоть до первой.
- **История.** `/{lang}/{slug}?history`: дата, автор, комментарий, размер правки (+/− символов).
- **Сравнение.** Любые две ревизии, построчный diff, как в git.
- **Откат.** Админ выбирает старую ревизию, её текст записывается как новая ревизия
  с комментарием «Откат к №12». Откат тоже можно откатить.
- **Удаление страницы** скрывает её от читателей. Админ видит её и может восстановить.

## Предложения правок

1. Читатель входит через GitHub и жмёт «Предложить правку» на странице.
2. Открывается редактор по адресу `/propose/{lang}/{slug}` (префикс, а не суффикс: у универсального маршрута статьи `/{lang}/{*slug}` суффикса быть не может) с текущим текстом. Предложение запоминает `base_rev_id`.
3. Предложение попадает в очередь со статусом `open`.
4. Админ видит diff предложенного текста против `base_rev_id` и против текущей ревизии.
5. **Принять:** создаётся ревизия, автор которой предложивший, а в комментарии указан принявший.
   Если текущая ревизия новее `base_rev_id`, админу показывается трёхстороннее сравнение
   (база, текущая, предложенная) и он правит итог сам. Автослияния нет.
6. **Отклонить:** статус `rejected` и причина. Автору видно решение на его странице «Мои предложения».

Вход: `GET /auth/github` ставит cookie `oauth_state` и отправляет на GitHub, `GET /auth/github/callback`
сверяет `state` с cookie (постоянное время), создаёт пользователя и сессию (cookie `sid`: HttpOnly,
SameSite=Lax, Secure при https в `PUBLIC_URL`). Админами становятся только пользователи, чей числовой
id GitHub указан в `ADMIN_GITHUB_IDS` (логин не учитывается: логины можно переименовать и занять),
понижать автоматически нельзя. Заблокированный пользователь сессию не получает. Сессия живёт не дольше
30 дней и гаснет после 7 дней без запросов. Права проверяются заново на каждом запросе, поэтому блокировка
и снятие прав действуют сразу.

CSRF: cookie с SameSite=Lax, и сверх того каждый POST (`/auth/logout`, `/propose/...`) с заголовком
`Origin`, не совпадающим с адресом из `PUBLIC_URL`, получает 403 (`http::user::check_origin`).
Отсутствующий `Origin` допускается.

Лимиты предложений: 5 открытых и 20 в сутки на человека (429), текст не больше 1 МиБ, комментарий не
длиннее 200 символов, текст должен отличаться от базовой ревизии.

Защита от спама: вход только через GitHub, не больше N открытых предложений на человека,
не больше M отправок в сутки, админ может заблокировать пользователя (`blocked_at`).

## Админка

Адрес `/admin`, доступ только у админов. Разделы:
- **Страницы:** дерево разделов, создание, правка, удаление, восстановление.
- **Редактор:** Markdown, живое превью через тот же `render`, кнопки вставки крафт-сетки,
  плашек подсказок и плашки версии.
- **Предложения:** очередь, diff, принять или отклонить. Решение атомарно: предложение сначала занимается
  (`status = 'open'` → итог одним UPDATE), потом сохраняется ревизия; при сбое сохранения предложение снова
  открывается. Повторное решение даёт 409. Принять предложение к удалённой странице нельзя (409), только отклонить.
- **Удаление и восстановление:** восстановление при живой странице с тем же адресом даёт 409.
- **История и откат** для любой страницы.
- **Ключи API:** создать (ключ показывается один раз), посмотреть последнее использование, отозвать.
- **Пользователи** (`/admin/users`): таблица (id, GitHub id, логин, админ, заблокирован) и действия
  `POST /admin/users/{id}/block`, `unblock`, `grant-admin`, `revoke-admin` (проверка `Origin`, право `ManageUsers`).
  Защита на сервере (409): админ не может заблокировать или понизить себя, последнего незаблокированного админа
  нельзя заблокировать или понизить. Блокировка действует со следующего запроса.
- **Картинки:** загрузка и список (`media`).

## API

Заголовок `Authorization: Bearer <ключ>`. Ответы в JSON, ошибки в формате
`{"error": "код", "message": "текст"}`.

| Метод и путь | Права | Назначение |
|---|---|---|
| `GET /api/pages` | read | Список страниц с актуальной ревизией |
| `GET /api/pages/{slug}?lang=ru` | read | Страница и метаданные |
| `PUT /api/pages/{slug}?lang=ru&summary=...` | write | Создать или обновить, тело запроса — Markdown; ответ `{"outcome": "created"\|"updated"\|"unchanged", "revision": id}` (без `revision` при `unchanged`) |
| `GET /api/revisions/{slug}?lang=ru` | read | История |
| `GET /api/export` | export | Все страницы архивом Markdown |

Запись через ключ создаёт обычную ревизию с автором «ключ: название». Если тело совпадает
с текущей ревизией, новая ревизия не создаётся (повторная заливка из CI безвредна).

Коды ошибок: 401 нет или неверный ключ, 403 не хватает прав, 404 нет страницы,
413 тело больше 1 МиБ, 422 неверный slug или язык, 429 лимит запросов (с заголовком `Retry-After`).

Тяжёлые чтения (сравнение версий `?diff=`, история `?history`, поиск) и запись через `PUT`
ограничены по клиенту: 60 запросов в минуту на ключ `diff:`, `history:`, `search:` с адресом из
`X-Real-IP` (иначе адрес сокета) и `put:` с id API-ключа. Обычный просмотр статьи не ограничивается.
Размер сравнения ограничен константой `MAX_DIFF_CELLS` (4 000 000 клеток таблицы LCS после отсечения
общих первых и последних строк); при превышении читатель видит уведомление со ссылками на обе версии.
