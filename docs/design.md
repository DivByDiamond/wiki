# OC2R Wiki: дизайн

Лицензия: GPL-3.0-or-later.

## Цель

Вики для мода OC2R (Minecraft, виртуальные RISC-V компьютеры) на `wiki.loki-code.dev`.
Аудитория: игроки и скриптеры. Разработчикам мода отдельный раздел не нужен.

Страницы хранятся не в файлах, а в базе. Правят их админы напрямую, читатели
отправляют предложения, внешние системы (CI, скрипты) пишут через API по ключу.
У каждой страницы полная история ревизий.

## Решения

| Вопрос | Решение |
|---|---|
| Платформа или вики одного мода | Вики одного мода. Мультитенантность не делаем |
| Бэкенд | Rust, axum, один бинарник |
| База | SQLite (WAL), поиск через FTS5 |
| Фронтенд | TypeScript без библиотек. Нужен только сборщик (esbuild) |
| Рендер Markdown | На сервере (pulldown-cmark), страницы работают без JS |
| Кто правит | Админы и API-ключи напрямую, остальные через очередь предложений |
| Вход | GitHub OAuth. Своих паролей нет |
| Версии Minecraft | Одна вики для всех. Отличия помечаются плашкой в тексте |
| Языки | en, ru, zh. Если перевода нет, показывается en с плашкой |
| Стиль | Чистая техдокументация (C) с заметными игровыми деталями (B) |

Платформу «вики для всех» не строим и под неё ничего не закладываем (YAGNI).

## Архитектура

```
Браузер ──HTTP──► Caddy ──► oc2r-wiki (axum)
                              ├─ http   маршруты, extractors, middleware
                              ├─ auth   GitHub OAuth, сессии, ключи, политика прав
                              ├─ domain типы и правила, порты (trait)
                              ├─ render Markdown → безопасный HTML
                              ├─ diff   сравнение текстов
                              └─ store  SQLite, реализует порты
```

Зависимости направлены внутрь: `http` и `store` знают про `domain`, `domain` не знает ни про кого.
Хранилище подключается через трейты из `domain/ports`, поэтому в тестах его заменяют
реализацией в памяти или временной базой.

Один конвейер рендера: `render::to_html(markdown) -> Html`. Его используют страница статьи,
просмотр старой ревизии, превью в админке и превью предложения. Второй путь рендера не создаём.

## Данные

SQLite, миграции в `server/src/store/sql/` применяются при старте по порядку номеров.

```
pages          id, slug, lang, section, position, current_rev_id, deleted_at, created_at
revisions      id, page_id, body, summary, author_kind, author_ref, created_at
               author_kind: user | api_key | import
proposals      id, page_id, base_rev_id, body, summary, user_id, status,
               decided_by, decided_at, decision_note, created_at
               status: open | accepted | rejected
users          id, github_id, login, role, blocked_at, created_at
               role: reader | admin
api_keys       id, name, key_hash, scope, created_at, last_used_at, revoked_at
               scope: read | write | export (набор флагов)
media          id, filename, mime, size, sha256, created_at
revisions_fts  FTS5 по body и slug, обновляется триггерами
```

Ограничения:
- Пара `(slug, lang)` уникальна среди неудалённых страниц.
- Ревизии не изменяются и не удаляются. Откат создаёт новую ревизию.
- Удаление страницы ставит `deleted_at`, история остаётся.
- Ключ хранится как SHA-256 от случайных 32 байт. Сам ключ показывается один раз.

## Деплой

- Один бинарник и файл базы. Статика фронтенда встраивается в бинарник при сборке.
- Caddy терминирует TLS для `wiki.loki-code.dev`. Конфиг и unit-файл systemd лежат в `deploy/`.
- Резервная копия: `sqlite3 .backup` раз в неделю и перед обновлением. Частота мала намеренно,
  потому что история правок уже защищает от ошибок в тексте.
- Экспорт всех страниц в Markdown через `GET /api/export` служит вторым способом копии.

## Вне объёма

Мультитенантность, открытая регистрация, комментарии под статьями, версии страниц по версиям
Minecraft, шаблоны страниц в стиле MediaWiki, плагины.
