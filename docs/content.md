# Содержимое вики

В бинарник включён `content/catalog.json`: 134 страницы (51 en, 47 ru, 36 zh).
Источник — чистая ревизия OC2R `fe96a9fcc5f81eedadfea415d8ae3aa0c907088a`.
Это снимок документации из локального проекта, не обещание доступности последнего релиза.

## Что включено

- Все 122 страницы встроенного руководства: начало, основы, блоки, предметы, сети, роботы, скрипты.
- Техническая документация: OnyxOS, Buildroot, Onyx RPC, устройства, сети и кабели.
- Отредактированные главные страницы на трёх языках.
- Обзор ОС на русском и английском; русские вводные по OnyxOS и `oc2ctl`.
- Таблица целей сборки на русском и английском по текущей дорожной карте, а не историческому плану.
- Семь изображений из руководства в `web/public/manual/`.

Ссылки `.md` становятся маршрутами вики, игровые `item:`/`block:` — текстовыми
идентификаторами предметов и блоков (веб-сайт не запускает игровой 3D-рендерер).
Технические документы сохраняют ссылки на файлы в исходной ревизии GitHub.
В каждой статье есть ссылка на источник. Пакет хранит путь и SHA-256 исходного файла.
Существующие переводы перенесены из OC2R; китайский перевод может отставать от английского.
Отсутствующие страницы доступны на английском с уведомлением о fallback.

## Первый запуск

```bash
(cd web && bun install --frozen-lockfile && bun run build)
cargo run -p oc2r-wiki
```

Открыть `http://127.0.0.1:8080/ru/start`. При первом запуске пустая SQLite-база
автоматически получает пакет. Непустая база при обычном запуске не меняется.
Для чтения и поиска GitHub OAuth не требуется. Для входа и редакторских функций
нужны переменные GitHub, описанные в README.

## Обновление из OC2R

```bash
python3 scripts/content/generate.py /storage/project/jvm/oc2r
python3 -m unittest discover -s scripts/content -v
(cd web && bun run build && bun run check && bun test)
cargo test --workspace
cargo build --release -p oc2r-wiki
```

Генератор требует чистую исходную ревизию, чтобы ссылки на GitHub точно описывали
перенесённый текст. Он не меняет OC2R. Просмотрите изменения в `content/catalog.json`
и `web/public/manual/` перед обновлением базы. В пакет попадают файлы, а не абсолютный
путь локального проекта; OC2R не нужен для сборки вики из готового checkout.

Редакторские статьи лежат в `content/overrides/<lang>/<slug>.md`. Первые две строки:
`source: путь/в/OC2R.md` и `source_sha256: SHA-256`. При изменении источника генератор
останавливается: сначала проверьте и обновите текст статьи, затем её контрольную сумму.
Так старое краткое изложение не получит новую ссылку на источник без проверки.

## Импорт в существующую базу

Сделайте резервную копию SQLite перед обновлением, затем выполните:

```bash
WIKI_DB=/absolute/path/wiki.db ./target/release/oc2r-wiki --sync-content
```

Команда завершится после импорта и выведет `created`, `updated`, `unchanged`, `protected`.
Она не запускает HTTP-сервер.

- Новые страницы добавляются с автором «импорт» и записью в истории.
- Изменения ранее импортированных этим пакетом страниц создают новые ревизии.
- Ручные правки и правки API защищены: их текущая версия не перезаписывается.
- Удалённые страницы защищены и не восстанавливаются импортом.
- Повторный импорт идентичного тела не создаёт новую ревизию.
- Весь пакет записывается одной транзакцией, включая полнотекстовый индекс.
- Отсутствие страницы в новом пакете не удаляет её из базы.

Для защищённой страницы сравните новое содержимое пакета с текущей статьёй и внесите
правку через редактор. Автоматического принудительного перезаписывания нет.
