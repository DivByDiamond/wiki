# Координаты и навигация робота

У робота есть локальная позиция и компас. Команды движения принимают направление относительно корпуса. Встроенной команды перехода к координатам нет.

## Прочитать положение

```lua
local r = require("robot")
local p = r.position()
print(p.x, p.y, p.z)
print(r.facing())
```

Начало координат задаётся при установке робота. `r.calibrate()` переносит его в текущую клетку: после этого `position()` возвращает `(0, 0, 0)`. При смене измерения начало отсчёта сбрасывается.

| Ось | Положительное направление | Отрицательное направление |
|---|---|---|
| X | Восток | Запад |
| Y | Вверх | Вниз |
| Z | Юг | Север |

Оси закреплены за миром. Если робот смотрит на север, шаг вперёд уменьшает Z. Поверните его направо: теперь шаг вперёд увеличит X.

Положение берётся из фактической клетки корпуса относительно сохранённого начала отсчёта. Это не счётчик команд. Читайте координаты после завершения движения, когда робот уже находится в нужной клетке.

## Можно ли получить обычные XYZ Minecraft

Через API самого робота нельзя получить его абсолютные XYZ. Получить координаты игрока этим API тоже нельзя.

В текущих исходниках есть [GPS-башня](/ru/block/gps_tower). Она сообщает мировые координаты собственного основания и идентификатор измерения. Башня не возвращает позицию игрока или робота. В рабочей версии добавляется [режим относительной радиосети](/ru/reference/gps-networks), но он пока определяет только смещения самих башен.

Если мировые координаты точки калибровки известны, сложите их с локальными:

```lua
local r = require("robot")

-- Здесь должны быть мировые координаты текущей клетки робота.
local origin = {x = 100, y = 64, z = -200}
r.calibrate()

local function worldPosition()
    local p = r.position()
    return {
        x = origin.x + p.x,
        y = origin.y + p.y,
        z = origin.z + p.z
    }
end

local p = worldPosition()
print(p.x, p.y, p.z)
```

Числа в примере условные. Такая привязка работает только при правильно указанном начале отсчёта. После новой калибровки или смены измерения её нужно задать заново. Координаты основания GPS-башни также нельзя подставлять как позицию робота без учёта смещения между ними.

## Как написать переход к точке

Сначала сравните `position()` с целью. По `facing()` определите, куда смотрит робот, и поверните его. Выполните один шаг и проверьте результат. Затем прочитайте позицию ещё раз.

В свободном пространстве можно проходить оси по очереди. Для работы среди препятствий понадобится карта и алгоритм поиска пути. Сканер помогает получить окружение, но не строит маршрут за программу.

Робот не получает команду добывать блок вместе с командой движения. Вызов `excavate()` относится к отдельному модулю. Программа сама решает, ломать препятствие, искать обход или остановиться.

## Назад на базу

Сохраните координаты базы и точку отсчёта в файле. Возврат к `(0, 0, 0)` имеет смысл только пока калибровка относится к базе. Не вызывайте `calibrate()` перед возвращением: иначе нулём станет текущее место.
