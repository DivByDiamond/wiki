# Первый робот

Сначала проверьте движение без дополнительных модулей. Потом подключайте добычу, инвентарь и сканер по одному. Так проще понять, какой компонент нужен программе.

## Сборка

Соберите [робота по рецепту](/ru/recipes#recipe-robot). В результате крафта уже установлена прошивка Linux. Если робот получен другим способом, проверьте наличие прошивки отдельно.

Для начала установите процессор и четыре модуля ОЗУ по 8 МиБ. Это практическая стартовая конфигурация для комплектного Linux. Отдельный жёсткий диск для его загрузки не нужен.

| Компонент | Число слотов |
|---|---|
| Процессор | 1 |
| ОЗУ | 4 |
| Flash-память с прошивкой | 1 |
| Жёсткие диски | 2 |
| Модули робота | 4 |
| Предметы | 12, номера от 0 до 11 |

Зарядите робота на [заряднике](/ru/block/charger), откройте терминал и включите питание. Дождитесь загрузки Linux и войдите как `root`. Компоненты меняйте при выключенной машине.

Робот не подключается к внешней интерфейсной шине. Для добычи, крафта и других операций нужны его собственные модули.

## Первая программа на Lua

В оболочке Linux настройте поиск комплектных библиотек:

```sh
export LUA_PATH="/mnt/builtin/lib/lua/?.lua;;"
lua
```

Файловая система `builtin` должна быть доступна в `/mnt/builtin`. Подробнее о библиотеке устройств читайте в разделе [скриптов](/ru/scripting).

Освободите клетку перед роботом. Введите в Lua:

```lua
local r = require("robot")
local ok = r.move("forward")
print("Движение:", ok)

local p = r.position()
print("Положение:", p.x, p.y, p.z)
print("Направление:", r.facing())
print("Энергия:", r.energy(), "/", r.capacity())
```

`move()` ждёт завершения. При успехе робот окажется на один блок впереди. Если вернулось `false`, проверьте свободное место и состояние машины.

## Пройти несколько блоков

```lua
local r = require("robot")

for step = 1, 5 do
    if not r.move("forward") then
        print("Остановка на шаге", step)
        break
    end
end
```

Проверяйте каждый шаг. После неудачи не считайте, что робот прошёл запланированное расстояние.

## Взять предмет из сундука

Установите модуль операций с инвентарём. Поставьте сундук с предметами прямо над роботом и выберите пустой слот:

```lua
local r = require("robot")
local d = require("devices")
local inv = assert(d:find("inventory_operations"), "Нет модуля инвентаря")

r.slot(0)
local taken = inv:take(1, "up")
print("Взято:", taken)

if taken > 0 then
    print("Возвращено:", inv:drop(taken, "up"))
end
```

Методы `take()` и `drop()` возвращают число перемещённых предметов. Проверяйте его: в сундуке может не оказаться нужного количества или свободного места. Без модуля можно выбирать слот и читать его содержимое, но переносить предметы нельзя.

## Осмотреть блок перед собой

```lua
local scanner = assert(require("devices"):find("scanner"), "Нет сканера")
local info = scanner:inspect("front")
print(info.block)
```

У модулей сторона перед роботом называется `front`. У команды движения используется `forward`. Это разные параметры.

## MicroPython

В `/mnt/builtin/lib/micropython` лежат `devices.py` и `robot.py`. Для Unix-порта MicroPython добавьте каталог в путь импорта:

```python
import sys
sys.path.append("/mnt/builtin/lib/micropython")

from devices import DeviceBus
from robot import robot

bus = DeviceBus("/dev/hvc0")
try:
    r = robot(bus)
    print(r.move("forward"))
    print(r.position())
finally:
    bus.close()
```

Интерпретатор должен быть установлен в гостевой ОС. Наличие файлов библиотеки само по себе его не устанавливает.

## C, C++ и другие языки

В `/mnt/builtin/lib/rpc` поставляются `rpc.c`, `rpc.h`, обёртка `rpc_raii.hpp` и примеры. Собирайте программы под гостевую RISC-V Linux. Библиотека позволяет найти устройство `robot` и вызвать его методы по имени.

Другой язык может использовать тот же JSON RPC через `/dev/hvc0`. Сообщения разделяются нулевым байтом. Для прямых `move` и `turn` нужно дождаться результата действия по его ID. Успешная отправка команды ещё не означает успешное движение.

В OnyxOS есть собственная утилита [oc2ctl](/ru/reference/onyx-rpc). Примеры для Linux не следует вводить в OnyxShell как команды оболочки.

## Если робот не выполняет программу

- При ошибке `module 'robot' not found` проверьте `LUA_PATH` и каталог `/mnt/builtin/lib/lua`.
- При `robot device not found` проверьте, что программа запущена внутри робота.
- Если не найден модуль, проверьте его установку и перезапустите гостевую ОС.
- Если `move()` вернул `false`, проверьте препятствия и питание.
- Если вызовы блока часто возвращают `false`, учитывайте [задержку модуля](/ru/item/block_operations_module).

Стандартные обёртки ожидают принятия и завершения команд без собственного тайм-аута. Для автономной программы с восстановлением после сбоев используйте прямое API, ограничивайте число попыток и сохраняйте состояние задачи.
