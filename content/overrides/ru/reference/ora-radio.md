# Радиосеть ORA

Радиосеть соединяет обычные кабельные сети через [GPS-башни](/ru/block/gps_tower) и передаёт кадры Ethernet, поэтому программы TCP/UDP на ПК работают без изменений. [Роботы](/ru/item/robot), [планшеты](/ru/item/tablet), [док-станция робота](/ru/block/charger) и [беспроводная точка доступа](/ru/block/wireless_access_point) подключаются к ней как радиоклиенты.

```text
ПК A → коннектор + синий кабель → вышка A ↔ вышка B ↔ вышка C → коннектор + синий кабель → ПК B
```

Регистрация в радиосети отделена от GPS: знание GPS UUID и вызов GPS `joinNetwork()` не разрешают передачу радиокадров. ORA не назначает гостям IP-адреса; IPv4 настраивается в госте отдельно.

## Покрытие

Вышки связываются на расстоянии до 45 блоков по горизонтали (`dx² + dz² <= 45²`), высота и стены не учитываются. X=45, Z=0 — связь есть; X=32, Z=32 — нет (около 45,25). Между измерениями связи нет. Для больших расстояний нужна цепочка зарегистрированных вышек. Выгруженная вышка продолжает ретранслировать по последнему известному положению, но компьютеры отправителя и получателя должны быть загружены; сеть чанки не загружает.

## Адреса ORA

**ORA = OC2R Radio Address**, запись вида `7K3F:02Q9`: четыре символа префикса сети и четыре символа номера узла из алфавита `0123456789ABCDEFGHJKMNPQRSTVWXYZ` (при вводе регистр не важен, `0000` зарезервирован). Сервер выбирает свободные значения случайно, сохраняет их с миром и не выдаёт повторно отозванные. Адрес — не пароль, не вычисляется из координат и не выходит за пределы измерения.

## Подключение

Первая настройка идёт через шину устройств вышки; такой физический доступ считается доверенным. Устройство `gps_tower` предоставляет:

| Метод | Назначение |
|---|---|
| `createRadioNetwork()` | создать сеть, вернёт `network` и `adminSecret` |
| `getRadioEndpointId()` | UUID узла для приглашения |
| `issueRadioInvite(adminSecret, endpointId)` | одноразовое приглашение, вернёт `invite` и `secret` |
| `joinRadioNetwork(invite, secret)` | подключить этот узел |
| `getRadioAddress()` / `getRadioStatus()` | адрес и состояние регистрации |
| `revokeRadioEndpoint(adminSecret, endpointId)` | отозвать один узел |

```lua
local tower = assert(require("devices"):find("gps_tower"))
-- первый ПК, один раз; сохраните adminSecret
local network = tower:createRadioNetwork()
local inv = tower:issueRadioInvite(network.adminSecret, "UUID-ВТОРОЙ-ВЫШКИ")
-- второй ПК
tower:joinRadioNetwork(inv.invite, inv.secret)
print(tower:getRadioAddress())
```

`find()` не выбирает ближайшую вышку; при нескольких подключённых используйте `devices:get(deviceId)`. Все промежуточные вышки тоже должны быть зарегистрированы.

### Регистрация с одобрением

`issueRadioInviteForApproval(adminSecret, endpointId, permissions, targetEndpointId, service)` создаёт приглашение, которое само никого не принимает. Подключаемое устройство вызывает `requestRadioEnrollment(invite, secret)`, создаётся ожидающий запрос без членства и прав. Затем решает администратор:

```lua
local pending = tower:listPendingEnrollments(adminSecret)
tower:approveEnrollment(adminSecret, pending[1].request, {"MESSAGE_SEND"})
-- или tower:denyEnrollment(adminSecret, pending[1].request)
-- на подключаемом устройстве после одобрения: tower:completeRadioEnrollment()
```

Вызывающая вышка должна быть зарегистрирована с правом `NETWORK_ADMIN` и знать секрет администратора. Устройство получает ровно одобренные права. На сеть допускается до 16 ожидающих запросов, по одному на устройство, каждый живёт 6000 тиков (пять минут). Адрес ORA выдаётся при одобрении.

## Роботы, доки, точки доступа и планшеты

- Робот подключается напрямую к вышке в радиусе вышки (`gps_tower_range`, 45). Иначе он цепляется к ближайшей [док-станции](/ru/block/charger) или [беспроводной точке доступа](/ru/block/wireless_access_point) в 10 блоках (`robot_dock_range`), у которой есть вышка той же сети в радиусе вышки. Радиусы не складываются, доки не ретранслируют между вышками.
- Доки и точки доступа не загружают чанки; сломанная или выгруженная сразу перестаёт учитываться.
- Через док робот управляется так же, как на вышке: телеметрия, команды, ping, список устройств, проверка прав. Выход из радиуса — потеря связи; отправленная в это время команда заканчивается как `DISCONNECTED` или `TIMED_OUT` и не повторяется.
- Результат команды робота определяется реальным действием: гость привязывает поставленное в очередь действие `move`/`turn` через `bindRadioCommand(requestId, actionId)`, а сервер сам выдаёт `COMPLETED` или `FAILED`, когда оно действительно закончилось.
- Личность планшета хранится в предмете: один активный держатель, при каждой активации новый секрет, поэтому копии не становятся второй личностью. Радио отключается, когда предмет никто не держит.

### Ethernet дока

Док принимает синий кабель через сетевой коннектор, но кабель сам ничего не подключает: у дока свой узел, и его надо пригласить. У устройства `charger` есть `getRadioEndpointId`, `joinRadioNetwork`, `getRadioAddress` и `getRadioStatus`. Кадры из коннекторов дока уходят в радиосеть через ближайшую вышку той же сети, а радиокадры записываются во все его коннекторы.

## Задержка, ping и лимиты

- Каждый переход занимает один тик, но общее время доставки ограничено `radioMaxDeliveryTicks` (2 тика, 100 мс при 20 TPS). Каждый отправитель ограничен `radioLinkBytesPerTick` (1024 Б/тик, около 20 КБ/с).
- `pingRadio(address, requestId)` измеряет реальный круговой путь; ответ приходит в `pollRadioEvents()` как `roundTripNanos`. `route.hops` и `route.nominalMillis` — оценки по расписанию.
- TTL перехода относится к сетевой шине OC2R и не связан с TTL в IP. Старые пакеты удаляются, очереди при перезапуске не сохраняются.
- **TLS не реализован.** `getRadioStatus()` сообщает `trusted-local-plaintext-no-tls`.
- Поля телеметрии показывают `ageTicks`, `ageMillis` и состояние `ONLINE`, `STALE` или `OFFLINE` (`getRadioTelemetryStatus(subscription)`).

Настройки лежат в секции `[gameplay]` общего конфига (после изменения лимитов радио перезапустите сервер):

```toml
gps_tower_range = 45
robot_dock_range = 10
radioHopDelayTicks = 1
radioMaxDeliveryTicks = 2
radioLinkBytesPerTick = 1024
radioMaxHops = 64
radioMaxFrameBytes = 2048
radioQueueLimit = 4096
radioNetworkQueueLimit = 1024
radioDeviceQueueLimit = 256
radioPacketLifetimeTicks = 200
```

Секреты — 256 случайных бит, реестр хранит только хеши SHA-256. Отзыв действует на одно устройство; повторное приглашение выдаёт новое поколение, адрес и секрет, а прежний секрет больше не проходит проверку.
