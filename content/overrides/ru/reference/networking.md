# Сетевой стек

В OC2R есть стек TCP/IP для виртуальных компьютеров и выход в обычный интернет с сервера и отдельный VXLAN-туннель. Эта статья описывает внутреннее устройство сети и настройки Internet Card. Для первого подключения компьютеров откройте [руководство по сетям](/ru/networking).

## Уровни сети

```text
Приложение
    ↓
Сеансы и сокеты TCP/UDP
    ↓
Транспорт: TCP или UDP
    ↓
Сетевой уровень: IPv4
    ↓
Канальный уровень: ARP
    ↓
Реальные сокеты сервера (интернет) · отдельно VXLAN-туннель для концентратора
```

## ARP и IPv4

`ArpProtocol` сопоставляет адреса IPv4 с MAC-адресами, обрабатывает ARP-запросы и ответы.

`DefaultNetworkLayer` отправляет, принимает и маршрутизирует пакеты. `Ipv4Space` описывает адресные пространства, подсети, диапазоны и CIDR. `MacAddress` представляет шестибайтовый MAC-адрес.

## TCP

Соединение TCP проходит через состояния, реализованные отдельными классами:

| Класс | Состояние |
|---|---|
| `AcceptState` | Ожидание входящего подключения |
| `ConnectState` | Установка подключения, включая SYN-SENT и SYN-RECEIVED |
| `EstablishedState` | Передача данных |
| `FinishState` | Закрытие, включая FIN-WAIT и CLOSE-WAIT |
| `ExpiredState` | Истечение времени ожидания |
| `RejectState` | Отправка или получение RST |

`TcpHeader` разбирает и записывает заголовки сегментов. `TcpState` описывает состояние отдельного соединения, `TcpStates` содержит стандартные экземпляры состояний, а `TcpUtils` работает с номерами последовательности.

## UDP и сеансы

UDP передаёт отдельные датаграммы и не использует автомат состояний TCP. Отправкой и приёмом занимается `DatagramSession`.

`DefaultSessionLayer` управляет сокетами, `SocketManager` выделяет временные порты, `SessionManager` управляет жизненным циклом сеансов.

| Вид сеанса | Реализация | Протокол |
|---|---|---|
| Потоковый | `StreamSessionImpl` | TCP |
| Датаграммный | `DatagramSessionImpl` | UDP |
| Эхо-запрос | `EchoSessionImpl` | ICMP echo |

Для ICMP используются `IcmpHandler`, `ICMPReply` и `EchoHandler`: обработка пакетов, создание эхо-ответов и ответы на ping.

## Выход во внешнюю сеть

`InternetManagerImpl` управляет сетевым потоком и соединениями. `InternetAdapter` связывает сеть виртуальной машины с внешней сетью. `DefaultInternetProvider` предоставляет стандартный способ подключения, а `InternetConnection` хранит состояние отдельного соединения.

### Что включить

1. В разделе `internet_card` общего конфига включите `internetCardEnabled`.
2. Установите Internet Card в компьютер либо поставьте блок Internet Gateway в сеть коннекторов.

Internet Card и Internet Gateway выходят в интернет прямо с сервера. VXLAN (`vxlan.enable`) им не нужен: это отдельная возможность для VXLAN-концентратора. Прежние заметки, где было написано иначе, ошибочны.

### Адрес, шлюз и DNS

Internet Card не предоставляет DHCP. Это соединение между двумя сторонами, для которого адрес задаётся вручную.

- Назначьте гостевой системе адрес, разрешённый настройками сервера.
- Карта отвечает на ARP-запросы со стороны шлюза, поэтому его адрес можно выбрать в соответствии со своей схемой.
- Встроенного DNS-резолвера у карты нет. В `/etc/resolv.conf` укажите `defaultNameServer` из настроек, по умолчанию `1.1.1.1`, либо другой доступный DNS-сервер.

Пример для гостевого Linux:

```sh
ip addr add 10.0.2.15/24 dev eth0
ip route add default via 10.0.2.2
echo "nameserver 1.1.1.1" > /etc/resolv.conf
ping 1.1.1.1
```

Замените имя интерфейса и адреса, если они отличаются в вашей конфигурации. Эти команды предназначены для Linux, а не для OnyxShell.

### Ограничение доступа

`deniedHosts` содержит запрещённые сети и адреса в формате CIDR. По умолчанию закрыты приватные диапазоны. Пакеты к запрещённым адресам отбрасываются без ICMP-ошибки.

`allowedHosts` включает обратный режим: если список непустой, разрешены только перечисленные назначения. Одновременно заполнять оба списка нельзя.

### Лимиты и время жизни

| Параметр | По умолчанию | К чему относится |
|---|---|---|
| `defaultSessionLifetimeMs` | 60 с | соединения, которые открываются или закрываются |
| `tcpEstablishedLifetimeMs` | 1 ч | установленные TCP-соединения |
| `datagramSessionLifetimeMs` | 15 с | UDP-обмены (DNS и подобное) |
| `defaultSessionsNumberPerCardLimit` | 32 | TCP-соединений на карту |
| `datagramSessionsNumberPerCardLimit` | 64 | UDP-обменов на карту; при переполнении самый старый сбрасывается |

Существующий файл конфига сохраняет прежние значения (раньше лимит на карту был 10), поэтому на давно настроенном сервере поднимите его вручную.

### Диагностика

| Симптом | Вероятная причина |
|---|---|
| `ping` не отвечает, хотя сеть работает | Нативный ping на сыром сокете требует root или `CAP_NET_RAW`. Без них сервер запускает системную команду `ping`, поэтому она должна быть установлена на сервере; в последнюю очередь используется JVM |
| Первый DNS-запрос всегда истекал по времени, следующие работали | Исправлено: датаграмма, открывавшая UDP-обмен, терялась |
| Большие DNS-ответы не доходят | Ответ длиннее одного кадра (около 1470 байт) обрезается и помечается как усечённый, резолвер повторяет запрос по TCP; остальной слишком большой UDP отбрасывается. Гостю нужен резолвер с TCP |
| Долгие SSH-сессии рвутся через минуту | Исправлено: установленные соединения живут `tcpEstablishedLifetimeMs` |
| Сеть замирает после пачки DNS-запросов | Исправлено: UDP-обмены больше не делят лимит с соединениями |
| DHCP-клиент сообщает о конфликте адреса | Исправлено: карта игнорирует пробы и объявления адреса |
| Соединение зависает без ошибки | TTL исчерпан по пути: приходит ICMP Time Exceeded |

## VXLAN

`VxlanBlockEntity` и `TunnelManager` передают Ethernet-кадры через туннель UDP. Приём пакетов выполняется в фоновом потоке. Несколько концентраторов различаются по VNI, идентификатору сети VXLAN.

- Туннель один на сервер: он привязан к `bindHost:bindPort` и связан с одним удалённым узлом `remoteHost:remotePort`. Датаграммы с других адресов отбрасываются ядром.
- У каждого концентратора случайный VNI. При регистрации сервер пишет в журнал строку «VXLAN hub at … uses VNI …»: именно этот номер нужно указать на другом конце.
- Порты выше 32767 работают (раньше они ломались).
- По умолчанию `vxlan.enable = false`, `remoteHost = 127.0.0.1`, порты 4789.

Чтобы подключиться с обычного ПК, на нём нужен VXLAN-интерфейс с тем же VNI, направленный на адрес сервера, например в Linux с правами root:

```sh
ip link add vx0 type vxlan id <VNI> remote <адрес-сервера> dstport 4789 srcport 4789 4789 local <адрес-ПК>
ip addr add 10.0.0.1/24 dev vx0
ip link set vx0 up
```

Параметр `srcport 4789 4789` обязателен: сервер принимает датаграммы только с адреса и порта `remoteHost:remotePort`, а ядро по умолчанию выбирает исходящий порт случайно. На сервере `remoteHost` должен быть адресом ПК, `remotePort` — 4789.

Гостю в игре назначьте адрес из той же сети (например `10.0.0.2/24`) и запустите там `sshd`. Тогда `ssh user@10.0.0.2` с ПК пойдёт через туннель. Кадры туннеля передаются без шифрования, поэтому не выставляйте порт в открытый интернет.

Для ICMP и UDP используется нативная библиотека `oc2rnet`. Если подходящей библиотеки нет, система переходит на реализацию средствами JVM. Доступность операций и поведение ICMP могут отличаться.

Комплектные файлы находятся в `src/main/resources/natives/`:

| Платформа | Файл |
|---|---|
| Linux x86_64 | `liboc2rnet-linux-x86_64.so` |
| Linux ARM64 | `liboc2rnet-linux-arm64.so` |
| macOS x86_64 | `liboc2rnet-x86_64.dylib` |
| macOS ARM64 | `liboc2rnet-arm64.dylib` |
| Windows x86_64 | `oc2rnet-x86_64.dll` |
| Windows ARM64 | `oc2rnet-arm64.dll` |
| Android ARM64 | `liboc2rnet-android-arm64.so` |
| Android x86_64 | `liboc2rnet-android-x86_64.so` |
