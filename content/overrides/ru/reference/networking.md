# Сетевой стек

В OC2R есть стек TCP/IP для виртуальных компьютеров и поддержка внешних соединений через VXLAN. Эта статья описывает внутреннее устройство сети и настройки Internet Card. Для первого подключения компьютеров откройте [руководство по сетям](/ru/networking).

## Уровни сети

```text
Приложение
    ↓
Сеансы и сокеты TCP/UDP
    ↓
Транспорт: TCP или UDP
    ↓
Сетевой уровень: IPv4
    ↓
Канальный уровень: ARP
    ↓
VXLAN ↔ нативная библиотека oc2rnet ↔ внешняя сеть
```

## ARP и IPv4

`ArpProtocol` сопоставляет адреса IPv4 с MAC-адресами, обрабатывает ARP-запросы и ответы.

`DefaultNetworkLayer` отправляет, принимает и маршрутизирует пакеты. `Ipv4Space` описывает адресные пространства, подсети, диапазоны и CIDR. `MacAddress` представляет шестибайтовый MAC-адрес.

## TCP

Соединение TCP проходит через состояния, реализованные отдельными классами:

| Класс | Состояние |
|---|---|
| `AcceptState` | Ожидание входящего подключения |
| `ConnectState` | Установка подключения, включая SYN-SENT и SYN-RECEIVED |
| `EstablishedState` | Передача данных |
| `FinishState` | Закрытие, включая FIN-WAIT и CLOSE-WAIT |
| `ExpiredState` | Истечение времени ожидания |
| `RejectState` | Отправка или получение RST |

`TcpHeader` разбирает и записывает заголовки сегментов. `TcpState` описывает состояние отдельного соединения, `TcpStates` содержит стандартные экземпляры состояний, а `TcpUtils` работает с номерами последовательности.

## UDP и сеансы

UDP передаёт отдельные датаграммы и не использует автомат состояний TCP. Отправкой и приёмом занимается `DatagramSession`.

`DefaultSessionLayer` управляет сокетами, `SocketManager` выделяет временные порты, `SessionManager` управляет жизненным циклом сеансов.

| Вид сеанса | Реализация | Протокол |
|---|---|---|
| Потоковый | `StreamSessionImpl` | TCP |
| Датаграммный | `DatagramSessionImpl` | UDP |
| Эхо-запрос | `EchoSessionImpl` | ICMP echo |

Для ICMP используются `IcmpHandler`, `ICMPReply` и `EchoHandler`: обработка пакетов, создание эхо-ответов и ответы на ping.

## Выход во внешнюю сеть

`InternetManagerImpl` управляет сетевым потоком и соединениями. `InternetAdapter` связывает сеть виртуальной машины с внешней сетью. `DefaultInternetProvider` предоставляет стандартный способ подключения, а `InternetConnection` хранит состояние отдельного соединения.

### Что включить

1. В общем конфиге включите VXLAN: `vxlan.enable`. Без него Internet Card не работает; начиная с 0.1.1 при запуске записывается предупреждение.
2. В разделе `internet_card` включите `internetCardEnabled`.
3. Установите Internet Card в компьютер.

В зависимости от схемы подключения также настройте VXLAN-концентратор. Не путайте внешний туннель с обычным обменом по локальной Ethernet-сети.

### Адрес, шлюз и DNS

Internet Card не предоставляет DHCP. Это соединение между двумя сторонами, для которого адрес задаётся вручную.

- Назначьте гостевой системе адрес, разрешённый настройками сервера.
- Карта отвечает на ARP-запросы со стороны шлюза, поэтому его адрес можно выбрать в соответствии со своей схемой.
- Встроенного DNS-резолвера у карты нет. В `/etc/resolv.conf` укажите `defaultNameServer` из настроек, по умолчанию `1.1.1.1`, либо другой доступный DNS-сервер.

Пример для гостевого Linux:

```sh
ip addr add 10.0.2.15/24 dev eth0
ip route add default via 10.0.2.2
echo "nameserver 1.1.1.1" > /etc/resolv.conf
ping 1.1.1.1
```

Замените имя интерфейса и адреса, если они отличаются в вашей конфигурации. Эти команды предназначены для Linux, а не для OnyxShell.

### Ограничение доступа

`deniedHosts` содержит запрещённые сети и адреса в формате CIDR. По умолчанию закрыты приватные диапазоны. Пакеты к запрещённым адресам отбрасываются без ICMP-ошибки.

`allowedHosts` включает обратный режим: если список непустой, разрешены только перечисленные назначения. Одновременно заполнять оба списка нельзя.

### Диагностика

| Симптом | Что проверить |
|---|---|
| `ping` не отвечает, хотя другие соединения работают | При запасной реализации ICMP средствами JVM без нужных прав или `CAP_NET_RAW` возможен ложный отрицательный результат. Предупреждение записывается один раз |
| Большие DNS-ответы не доходят | В исправленной реализации возвращается ICMP-сообщение о необходимости фрагментации при MTU 1500. Старые сборки могли молча терять фрагменты |
| Соединение зависает без ошибки | Проверьте TTL. При его исчерпании исправленная реализация отвечает ICMP Time Exceeded |
| Ответ о недоступном порте приходит от `0.0.0.0` | В 0.1.1 это исправлено: ответ использует адрес недоступного узла |

## VXLAN

`VxlanBlockEntity` и `TunnelManager` передают Ethernet-кадры через туннель UDP. Приём пакетов выполняется в фоновом потоке. Несколько интерфейсов различаются по VNI, идентификатору сети VXLAN.

Для ICMP и UDP используется нативная библиотека `oc2rnet`. Если подходящей библиотеки нет, система переходит на реализацию средствами JVM. Доступность операций и поведение ICMP могут отличаться.

Комплектные файлы находятся в `src/main/resources/natives/`:

| Платформа | Файл |
|---|---|
| Linux x86_64 | `liboc2rnet-linux-x86_64.so` |
| Linux ARM64 | `liboc2rnet-linux-arm64.so` |
| macOS x86_64 | `liboc2rnet-x86_64.dylib` |
| macOS ARM64 | `liboc2rnet-arm64.dylib` |
| Windows x86_64 | `oc2rnet-x86_64.dll` |
| Windows ARM64 | `oc2rnet-arm64.dll` |
| Android ARM64 | `liboc2rnet-android-arm64.so` |
| Android x86_64 | `liboc2rnet-android-x86_64.so` |
